# dialysis-aut

Code, benchmark graphs, scripts and results for

> C. I. Karatzas, *Refinement-Derived Algebraic Computation of Graph Automorphism Groups*, preprint, Zenodo, 2026.
> [doi:10.5281/zenodo.23146211](https://doi.org/10.5281/zenodo.23146211)

and its extension (see [Extension: practical algorithm with an explicit bound](#extension-practical-algorithm-with-an-explicit-bound))

> C. I. Karatzas, *A practical graph isomorphism solver and an explicit quasi-polynomial bound*, preprint, Zenodo,
> 2026. [doi:10.5281/zenodo.23458588](https://doi.org/10.5281/zenodo.23458588)

The method computes the automorphism group of a graph exactly, with a verified generating set:

1. **Refinement-derived permutation groups.** Inside each class of an invariant colouring, individualisation and
   refinement give a set `T_C` of permutations containing the restriction of every automorphism; it is checked to be a
   group.
2. **Algebraic solver.** A normal series of every `T_C` with elementary abelian factors turns the edges between classes
   into affine systems over finite fields, solved level by level and counted by cosets (the classical
   bounded-colour-multiplicity tower method, applied where bounded multiplicity is not given).
3. **Decomposition-guided stabiliser chain.** Where the `T_C` are too large, roots taken from the recursive
   decomposition (dialysis) are individualised until the solver is exact on their stabiliser; root orbits are decided
   by a two-sided coset solve.
4. **Decomposition-derived invariants** for projective and affine planes (nets).
5. **Starting colouring (plug-in).** The solver and the chain start from any invariant colouring: plain colour
   refinement (1-WL) or the structural colouring `PI` derived from the dialysis of every vertex.

Every reported group order is exact; every generator is verified edge by edge on the input graph. `Traces` is used
only as a separate oracle, never inside the method. One exception, in the extension only: the optional generator
shortcut `SERIES_GENAUT=1` computes the order of the group generated by verified automorphisms with nauty's
`schreier.c` (through `TracesJni.groupOrderFromGenerators`); the generators themselves come from our search.

## Requirements

Linux x86-64, JDK 17 or newer, `gcc`/`g++` (the three JNI libraries are built from source), Python 3 (scripts and
checks). Memory: 4 GB is enough for most instances; the largest (`pp` of order 27, graphs with 10,000 vertices) need
about 8 GB.

## Build

```
./gradlew paperJar                 # -> build/libs/dialysis-paper3.jar
scripts/run_gradle.sh paperJar     # the same inside a memory-capped systemd scope (recommended on a desktop)
```

The jar is self-contained (Kotlin runtime, jgrapht, native libraries, code). The native libraries are compiled with
`-march=native`: build on the machine that runs the experiments. `./gradlew test` is disabled on purpose: the
experiment classes in `src/test` are whole campaigns, run through the jar.

## Quick start

The graphs are in `graphs/<family>/` (DIMACS format). One family through the whole pipeline, results in
`results-run/<family>/`:

```
JAR=build/libs/dialysis-paper3.jar GRAPHS=graphs OUT=results-run TMP_DIR=./tmp \
    scripts/xeon/run_family.sh johnson
python3 scripts/xeon/summarize.py results-run graphs      # per-family table: results-run/summary.md
```

`run_family.sh` runs stage 1 (the algebraic solver alone) on every instance and stage 2 (the stabiliser chain) on
every instance stage 1 did not solve. It is resumable: stop it any time and run the same command again. Per instance
the outputs are a row of `series.csv` (stage 1: status, `aut_log2`, orbits, time) and, for stage 2,
`chain/<instance>.<colour>.txt`, whose last line is `|Aut| = ... ours <seconds>`.

The JVMs get bounded heaps (`SERIES_HEAP` [6g], `CHAIN_HEAP` [3g], `CHAIN_JOBS` [2] in parallel). On a desktop, run the
script inside a memory-capped scope so that a large instance cannot take the machine down:

```
systemd-run --user --scope -p MemoryMax=8G -p MemorySwapMax=0 \
    env JAR=build/libs/dialysis-paper3.jar GRAPHS=graphs OUT=results-run TMP_DIR=./tmp scripts/xeon/run_family.sh <family>
```

`scripts/xeon/README.md` lists every family with the settings used in the paper (starting colouring, budgets,
threads, options such as `CHAIN_PRUNE`, `CHAIN_COMPLEMENT`, `CHAIN_AFFINE`) and what each output file contains.

### Other entry points

```
java -jar build/libs/dialysis-paper3.jar series   # algebraic solver alone on a family    (env: FAMILY, DIR, OUT, ...)
java -jar build/libs/dialysis-paper3.jar chain    # stabiliser chain on instances          (env: SC_FILES, OUT, ...)
java -jar build/libs/dialysis-paper3.jar oracle   # Traces on one instance (separate oracle; env: TR_FILE, TR_COLOUR, OUT)
java -jar build/libs/dialysis-paper3.jar traces --family=<f> --out=<csv> --timeoutMs=<ms>   # Traces oracle on a family
java -jar build/libs/dialysis-paper3.jar run <Class> <method>                             # any experiment method
GRAPHS=graphs scripts/xeon/run_traces_all.sh                                             # Traces oracle, every family
```

Settings are environment variables; `run_family.sh` and `scripts/xeon/README.md` document them.

## Graphs

`graphs/` holds the 12,001 instances of the 36 families of the paper; `graphs/SHA256SUMS` lists every file with its
checksum (`cd graphs && sha256sum -c SHA256SUMS`). Sources: the `nauty`/`Traces` benchmark collection of McKay and
Piperno (most families, including the CFI-type families of Neuen and Schweitzer and `Aff25`), the `conauto` collection
(`tnn`, `chh`), Moorhouse's list of projective planes (`pp`), the censuses of 4-valent arc-transitive (n <= 640,
`quartic-at`) and half-arc-transitive (n <= 1000, `quartic-hat`) graphs of Potočnik, Spiga and Verret, and House of
Graphs (`quartic-hog`); `quartic-validation` is the Coxeter graph. The files are redistributed unmodified; please
cite the original collections when you use them. Two families were generated for the paper: `graphs/johnson`
(Johnson graphs J(n,k), k = 3..6) and `graphs/hypercube` (Q_3..Q_13), both with seeded random vertex numbering; their
orders have closed forms (n!, doubled when n = 2k; 2^d d!). Family folders keep the names of the downloaded archives;
the paper's `grid-sw` is the folder `grid-w` (tori with wrap-around, orders (2m)^d d!).

## Extension: practical algorithm with an explicit bound

This section belongs to the second paper (title above). It extends the pipeline of the first paper; nothing
of the first paper's behaviour changes unless the options below are set (all of them are opt-in, including the candidate
cap `SERIES_CAND_WORK`; the second paper's runs set `SERIES_CAND_WORK=2000000000`).

What the extension adds:

1. **Permutation-group layer** (`dialysis/group/PermGroup.kt`): stabiliser chains with Schreier vectors, deterministic
   Schreier-Sims, randomised Schreier-Sims with a known target order (exact by order match), block systems, restriction to
   a window and lifting, a per-level budget for cached coset representatives (`GROUP_CACHE_INTS`).
2. **Luks' string / edge-set isomorphism** (`dialysis/group/LuksIso.kt`): intransitive and transitive steps, branching
   over a block stabiliser for large primitive quotients, window restriction, a cache of the window restriction and lazy
   lifts (generators plus exact order), and counters of the giant primitive quotients met.
3. **(D) route** (`DecompositionCanonicalFormsTest.luksAutOf`): an Aut-invariant edge class (1-WL colour pair) whose
   removal splits a component cuts the graph into pieces; pieces are typed up to isomorphism, one representative per type
   is solved, the quotient of piece permutations is solved, and Luks matches the cut edges inside the product of the
   piece groups (generator-lift shortcut, exact coset pruning, glue types, a cap that hands the level back to the chain).
4. **Recursion inside the pieces** (`autRec`, `isoRec`, `LUKS_RECURSE=1`): piece groups and piece isomorphisms are
   decided by the same pipeline recursively; an undecided piece isomorphism makes the route fail, never typing pieces apart.
5. **Star route** (`luksStarAutOf`, `autByComponents`): per colour class the star structure (the class plus one node per
   distinct neighbourhood trace of every other class) as an ambient group, then Luks over the product.
6. **Series solver additions**: generator-based pruning of the candidate DFS (`SERIES_AUTPRUNE`), derived candidate sets
   (`SERIES_DERIVE`), the generator shortcut (`SERIES_GENAUT`), and a work-based cap on the candidate DFS that hands over
   to the generator-based IR fallback (`SERIES_CAND_WORK`).
7. **Fallback order** when the series solver stops: (D) route (`SERIES_LUKS=1`), then star route (`SERIES_STAR=1`);
   with `SERIES_LUKS_PLAIN=1` Luks' method runs from the uniform colouring first.
8. **Leaf-group pruning** (`SERIES_TCPRUNE`, `SERIES_TCGROUP`): the candidate search is pruned by the group generated by
   the leaf maps. With admissibility checked on all vertices (`SERIES_ADMIT_V=1`) the leaf maps form a group (the
   paper's Proposition on leaf maps with admissibility on V), so the pruning is unconditional; without it, results are
   reported as COND_EXACT (conditional on Conjecture 11.1 of the first paper).
9. **Chain search for group tables** (`PieceProfileTest`, class-2 runs): stabiliser-orbit pruning of refuted images
   (`SC_STABPRUNE`) and a canonical-cell lookahead (`SC_LOOKAHEAD`, with `SC_FASTNODE=1`; `SC_LOOK_FRAC` bounds its
   share of the work); `SC_QUERY_MS` is the query-phase budget.

### Running the extension

Copy-paste examples with their expected output are in *Worked examples* below. All drivers run through the same jar (`java -jar build/libs/dialysis-paper3.jar run <Class> <method>`). On a desktop use
`scripts/safe_java_test.sh UNIT HEAP_MB CLASS METHOD LOG`, which starts one JVM with `-Xmx HEAP_MB` inside a systemd
scope capped at HEAP+450 MB, watches anonymous memory and the system's free memory, and refuses to start if not enough
memory is free (keep the heap well below what is free). For the large A5 instances use the serial collector
(`JAVA_TOOL_OPTIONS=-XX:+UseSerialGC`).

```
scripts/run_gradle.sh paperJar
# (D) route on a list of instances, with the Traces oracle on the same graphs:
INSTANCES_FILE=list.txt LUKS_TRACES=1 SERIES_AUTPRUNE=1 SERIES_DERIVE=1 SERIES_GENAUT=1 \
    scripts/safe_java_test.sh d1 1000 dialysis.experimental.DecompositionCanonicalFormsTest luksFullAut d1.log
# the same with recursion inside the pieces (needed for the SRG-block graphs):
LUKS_RECURSE=1 INSTANCES_FILE=list.txt ... luksFullAut ...
# star route (forced even when a class holds the majority):
STAR_IGNORE_MAJORITY=1 INSTANCES_FILE=list.txt ... luksStarAut ...
# one instance through the series solver with PI and the IR fallback:
ONE_PATH=graph.dimacs ONE_DEADLINE_S=1200 scripts/safe_java_test.sh s1 1000 \
    dialysis.experimental.DecompositionCanonicalFormsTest seriesOne s1.log
```

| driver (`DecompositionCanonicalFormsTest.`) | what | output lines |
|---|---|---|
| `luksFullAut` | (D) route on every file of `INSTANCES_FILE` | `LUKSAUT <name> \|Aut(G)\| = ...`, `GIANTS ...` |
| `luksStarAut` | star route on every file of `INSTANCES_FILE` | `STARAUT <name> \|Aut\| = ... Traces ... agree=...` |
| `luksAblation` | Luks routes with the first k greedy roots individualised (`ABL_FILE` from `scripts/paper4/export_roots.py`) | `ABL <name> k=...` |
| `seriesOne` | series solver on one instance (`ONE_PATH`) | `ONE <path> -> <status> \|Aut\|=...` |

| flag | default | meaning |
|---|---|---|
| `INSTANCES_FILE` | - | file with one graph path per line (drivers above) |
| `LUKS_PIECE_S` | 600 (300 in `luksAblation`) | deadline per piece / star / quotient solve, seconds |
| `LUKS_RECURSE` | 0 | 1 = recursion inside the pieces (`autRec`, `isoRec`) |
| `LUKS_RECURSE_DEPTH` | 3 | maximal recursion depth |
| `ISO_IR_NODES` | 200000 | node cap of the IR piece-isomorphism search before the recursion |
| `LUKS_GLUE` | 1 | 0 = no glue types on the quotient |
| `GLUE_MAX` | 200000 | cap on the restricted-group pairs used for glue types |
| `LUKS_GLUE_MAX_TESTS` | 200 | coset tests on the quotient before the level is handed back to the chain |
| `LUKS_TRACES` | 0 | 1 = print the Traces oracle order next to ours (`luksFullAut`) |
| `LUKS_MEM` | 0 | 1 = print the used heap on every log line |
| `LUKS_KERNEL_BRANCH_MAX` | 64 | quotient size above which Luks branches over a block stabiliser instead of the kernel |
| `LUKS_DIAG` | unset | set = diagnostic output for windows of >= 1000 points |
| `GROUP_CACHE_INTS` | 4000000 | per chain level and direction, ints of cached coset representatives (500000 for the A5 runs) |
| `STAR_IGNORE_MAJORITY` | 0 | 1 = run the star route even when one class holds more than half the vertices |
| `STAR_TRACES` | 1 | 0 = skip the Traces oracle in `luksStarAut` |
| `SERIES_LUKS` | 0 | 1 = on a series stop, try the (D) route |
| `SERIES_STAR` | 0 | 1 = if the (D) route does not apply, try the star route |
| `SERIES_AUTPRUNE` | 0 | 1 = generator-based pruning of the candidate DFS |
| `SERIES_DERIVE` | 0 | 1 = derive later classes' candidate sets from full maps |
| `SERIES_GENAUT` | 0 | 1 = generator shortcut (Aut = verified leaf automorphisms; order by nauty's `schreier.c`) |
| `SERIES_CAND_WORK` | unset (off) | set (second paper: 2e9) and with the IR fallback on: the candidate DFS is capped at max(20000, value / (n + m)) nodes, then hands over to IR |
| `SERIES_MAX_COMBOS` | 4096 | combination cap of the series solver |
| `SERIES_MAX_NODES` | 200000 | node cap of the series solver's queries |
| `ABL_FILE`, `ABL_KS`, `ABL_TRACES` | -, 0,1,2,3,4,6,8, 0 | `luksAblation`: roots file, numbers of roots, Traces oracle |
| `SERIES_LUKS_PLAIN` | 0 | 1 = on a series stop, Luks' method from the uniform colouring first |
| `SERIES_TCPRUNE`, `SERIES_TCGROUP` | 0 | leaf-group pruning; leaf maps as generators and Aut by Luks in their product |
| `SERIES_ADMIT_V` | 0 | 1 = admissibility checked on all vertices (makes `SERIES_TCPRUNE` unconditional) |
| `ONE_PATH`, `ONE_DEADLINE_S`, `ONE_USE_PI`, `ONE_MAX_BASE`, `ONE_MAX_CAND` | - | `seriesOne`: instance, deadline, PI or 1-WL start, caps |
| `SC_FASTNODE`, `SC_RESET`, `SC_RESET_SKIP` | 0 | chain (`PieceProfileTest`): cached-domain node checks, adaptive reset (class-2 stress runs) |
| `SC_STABPRUNE`, `SC_LOOKAHEAD`, `SC_LOOK_FRAC` | 0, 0, 1.0 | chain: stabiliser-orbit pruning of refuted images; canonical-cell lookahead and its work share |
| `SC_QUERY_MS` | 3600000 | chain: query-phase budget in ms |

### Worked examples

The expected lines are copied from the paper's runs (logs in `results/`); only the times depend on the machine. Run them from the repository root, after `scripts/run_gradle.sh paperJar`. Instances go into a
work folder outside the repository; here `$HOME/aut-work`.

**Step 0: make two small instances.** The S3 group-CFI graph on a random cubic graph with 12 vertices (seed 1), without
and with a twist; 648 vertices each.

```
mkdir -p $HOME/aut-work
python3 scripts/paper4/gen_group_cfi.py $HOME/aut-work S3:rc12-1 S3:rc12-1:tw
```

This writes `$HOME/aut-work/gcfi-S3-rc12-1` and `$HOME/aut-work/gcfi-S3-rc12-1-tw` (DIMACS, first line
`p edge 648 1404`).

**Example 1: one graph through the full flow of the paper** (the `tcgl` method; also the smoke test of a build).

```
SERIES_TCPRUNE=1 SERIES_ADMIT_V=1 SERIES_TCGROUP=1 SERIES_AUTPRUNE=1 SERIES_GENAUT=1 \
SERIES_LUKS=1 SERIES_LUKS_PLAIN=1 LUKS_PIECE_S=600 LUKS_GLUE_MAX_TESTS=2000 \
ONE_PATH=$HOME/aut-work/gcfi-S3-rc12-1 ONE_DEADLINE_S=150 ONE_USE_PI=1 IR_FALLBACK=0 ONE_MAX_BASE=24 ONE_MAX_CAND=2000000 \
scripts/safe_java_test.sh ex1 1000 dialysis.experimental.DecompositionCanonicalFormsTest seriesOne $HOME/aut-work/ex1.log
```

What the settings mean:
- `SERIES_TCPRUNE=1 SERIES_ADMIT_V=1`: leaf-group pruning, with admissibility checked on all vertices, so the answer
  is unconditional (EXACT). With `SERIES_TCPRUNE=1` alone the answer is COND_EXACT, conditional on Conjecture 11.1 of
  the first paper.
- `SERIES_TCGROUP=1 SERIES_AUTPRUNE=1 SERIES_GENAUT=1`: the series solver's group-building options.
- `SERIES_LUKS=1 SERIES_LUKS_PLAIN=1`: if the series stage stops, hand over to Luks' method, starting from the uniform
  colouring.
- `ONE_DEADLINE_S`: the series stage's budget in seconds (the paper used a quarter of the run's timeout);
  `LUKS_PIECE_S` is the budget of the Luks stage.
- `ONE_USE_PI=1`: start from the colouring PI (use 0, plain 1-WL, above about 8,000 vertices).
- Positional arguments of `safe_java_test.sh`: a unit name (any unused name), the heap in MB, the class, the method,
  the log file.

`cat $HOME/aut-work/ex1.log` should end with (7 s on the Xeon):

```
ONE .../gcfi-S3-rc12-1 original=true -> EXACT |Aut|=36.0000 vars=0 TCGROUP: Aut = Stab_P(E), |P| = ... (6.734s)
EXIT 0
```

The twisted graph gives `EXACT |Aut|=12.0000`. The status is EXACT (proved), COND_EXACT (proved if Conjecture 11.1
of the first paper holds) or one of the `STOP_...` reasons (no answer within the limits). `EXIT 3` means the script
refused to start because too little memory is free: it needs the heap + 450 MB + `FLOOR_MB` (default 2000) free. On
a busy desktop, `FLOOR_MB=500` in front of the command lowers that; the watchdog then stops the run (`EXIT 91`) if free
memory falls below 500 MB. `EXIT 90` means the job needed more than its heap.

**Example 2: the (D) route alone on a list of graphs.**

```
ls $HOME/aut-work/gcfi-* > $HOME/aut-work/list.txt
INSTANCES_FILE=$HOME/aut-work/list.txt SERIES_AUTPRUNE=1 SERIES_TCGROUP=1 SERIES_GENAUT=1 LUKS_PIECE_S=600 \
scripts/safe_java_test.sh ex2 1000 dialysis.experimental.DecompositionCanonicalFormsTest luksFullAut $HOME/aut-work/ex2.log
grep "|Aut(G)|\|GIANTS" $HOME/aut-work/ex2.log
```

Expected (about 1 s each):

```
LUKSAUT gcfi-S3-rc12-1 GIANTS giants=0 maxGiantDeg=0 maxQuotDeg=3
LUKSAUT gcfi-S3-rc12-1 |Aut(G)| = 36 | luks: 12 pieces, 1 types, |Q| = 4, |image| = 1, 4 iso tests, 0.893s
LUKSAUT gcfi-S3-rc12-1-tw GIANTS giants=0 maxGiantDeg=0 maxQuotDeg=3
```

**Example 3: the Traces oracle on one graph** (separate from our solver; only for checking).

```
TR_FILE=$HOME/aut-work/gcfi-S3-rc12-1 TR_COLOUR=none OUT=$HOME/aut-work/traces.csv \
scripts/safe_java_test.sh ex3 1000 dialysis.experimental.TracesOracle tracesOne $HOME/aut-work/ex3.log
```

Expected: `TRACES gcfi-S3-rc12-1 colour=none classes=1 colour_ms=0 |Aut|=36.0 traces_ms=...`, and a row in
`traces.csv`.

**Example 4: isomorphism test by one automorphism-group computation** (the paper's Lemma on isomorphism by automorphisms).
Put the two graphs side by side and compute the automorphism group of the union. For connected G and H of the same
size, G and H are isomorphic exactly when |Aut(G + H)| = 2 |Aut G| |Aut H|; otherwise |Aut(G + H)| = |Aut G| |Aut H|.

```
python3 scripts/paper4/gen_group_cfi.py $HOME/aut-work S3:rc16-1 S3:rc16-1:tw
python3 scripts/paper4/disjoint_union.py $HOME/aut-work/gcfi-S3-rc16-1 $HOME/aut-work/gcfi-S3-rc16-1 $HOME/aut-work/pair-iso 7
python3 scripts/paper4/disjoint_union.py $HOME/aut-work/gcfi-S3-rc16-1 $HOME/aut-work/gcfi-S3-rc16-1-tw $HOME/aut-work/pair-noniso
ls $HOME/aut-work/pair-* > $HOME/aut-work/pairs.txt
INSTANCES_FILE=$HOME/aut-work/pairs.txt SERIES_AUTPRUNE=1 SERIES_TCGROUP=1 SERIES_GENAUT=1 LUKS_PIECE_S=600 \
scripts/safe_java_test.sh ex4 1000 dialysis.experimental.DecompositionCanonicalFormsTest luksFullAut $HOME/aut-work/ex4.log
```

The last argument of the first `disjoint_union.py` call (7) relabels the second copy by a random permutation, so the
pair is isomorphic but not identical. Each union has 1,728 vertices. Expected (the paper's table of isomorphism
pairs; under a minute each): `pair-iso` gives `|Aut(G)| = 3359232` = 2 x 1,296 x 1,296 (isomorphic), `pair-noniso`
gives `|Aut(G)| = 559872` = 1,296 x 432 (the twisted graph is not isomorphic to the untwisted one). An isomorphism itself is any generator of the group that maps a vertex of the first copy into the
second.

**Example 5: the paper's G2 attack in batch** (a server with memory; one JVM per run, each with its own timeout).

```
mkdir -p $HOME/g2/inst $HOME/g2/tmp
python3 scripts/paper4/gen_group_cfi.py $HOME/g2/inst S3:rc12-1 S3:rc12-1:tw A5:K4 A5:K4:tw F3_2:mcgee F3_2:mcgee:tw
INST=$HOME/g2/inst OUT=$HOME/g2/out JAR=$PWD/build/libs/dialysis-paper3.jar METHODS="tcgl luks traces" \
  JOBS=1 HEAP=4g TIMEOUT_S=7200 TMP_DIR=$HOME/g2/tmp scripts/xeon/oct17/run_g2_attack.sh
cat $HOME/g2/out/summary.txt
```

It writes one log per run (`tcgl_<instance>.log`, `luks_<instance>.log`, `traces_<instance>.log`) and skips runs that
already finished, so it can be stopped and restarted. A5-K4 (15,120 vertices) takes about 80 s by the (D) route on the
Xeon, with `|Aut(G)| = 57600` and `maxGiantDeg=5`; the A5 graphs need 1.05 to 1.3 GB of heap. The other methods and
the paper's 30 instances are listed in `scripts/xeon/oct17/README.md`; the paper's logs are in
`results/xeon-2026-10-g2/`.

### Reproducing the extension's tables

Scripts are in `scripts/paper4/` (Python 3; GAP with the GRAPE package for `local_groups.py`, `tstar.py`,
`deep_star.py`, `dichotomy.py`; numpy for `muz_aut_predict.py`). Instances are generated into a directory of your
choice; nothing is written into the repository.

| table / figure | how |
|---|---|
| explicit constants, exact sums | `python3 scripts/paper4/composition.py` |
| group-CFI stall cases (S3, A5) | `gen_group_cfi.py OUTDIR S3:rc16-1 S3:rc16-1:tw A5:K33 ...`, then `luksFullAut` with `SERIES_AUTPRUNE/DERIVE/GENAUT=1` (A5: serial GC, `GROUP_CACHE_INTS=500000`) |
| SRG-block graphs | `gen_srg_blocks.py OUT a b "types"`, then `luksFullAut` with `LUKS_RECURSE=1` |
| chh-type graphs | `gen_chh_like.py scripts/paper4/data/chh_templates.json OUT a b "n1,n2;..."` |
| voltage covers, SQS covers | `gen_voltage_cover.py OUT m GROUP MODE SEED`, `gen_sqs_cover.py OUT GROUP SEED`, then `seriesOne` with `SERIES_CAND_WORK=2000000000` (the J(19)/J(31) timings need the cap) |
| isomorphism pairs | `disjoint_union.py G H OUT [relabel_seed]`, then the route that solves G |
| star groups d_k, certificates t*, deeper stars, dichotomy test | `local_groups.py`, `tstar.py`, `deep_star.py`, `dichotomy.py` (GAP/GRAPE; they share `split_classify.py`) |
| Muzychuk-CFI predicted orders | `gen_muz_cfi.py`, `muz_aut_predict.py` |
| comparison with Traces per family (where Traces is faster, where it stops) | `python3 scripts/paper4/traces_compare.py` (reads `results/xeon-2026-10` and `results/traces-paper1`) |
| G2 attack, group-CFI on high-girth bases, ablation of the leaf-group pruning | `scripts/xeon/oct17/run_g2_attack.sh` (README there); results in `results/xeon-2026-10-g2/` |
| random class-2 groups (look mode, orders 128 to 256) | `scripts/xeon/stress/run_stress.sh`, `aut_group_check.py` (README there); results in `results/xeon-2026-10-class2/` |

The generators in `scripts/paper4/` produce diagnostic instances for the extension; they are not benchmark families and
are not part of `graphs/`.
